# 공유 파일 형식 v1

2026-09-11, EnvHandoff 0.0.1 구현 기준. 제품 기능 단계와 앱 버전과는 별개의 파일 형식 버전이다. 웹 구현은 `apps/web/src/lib/bundle.ts`, 독립 테스트 벡터는 `fixtures/bundles/v1.json`을 기준으로 한다.

## 바이트 배치

모든 길이는 바이트 수다. `.envhandoff`는 아래 바이트를 그대로 이어 붙인다. 압축·ZIP·외부 파일 참조를 사용하지 않는다.

| 오프셋 | 길이 | 값 |
|---|---|---|
| 0 | 10 | ASCII `ENVHANDOFF` |
| 10 | 2 | unsigned 16-bit big-endian 형식 버전, `00 01` |
| 12 | 12 | CSPRNG로 생성한 nonce |
| 24 | 가변 | AES-256-GCM 암호문 |
| 끝에서 16 | 16 | GCM 인증 태그 |

앞의 24바이트 전체를 AES-GCM의 AAD로 넣는다. nonce는 공개해도 되는 값이며 AAD에도 포함한다. 새 묶음을 생성할 때마다 독립적인 32바이트 키와 12바이트 nonce를 생성한다. Web Crypto의 `AES-GCM`, `tagLength: 128`을 사용하고 키는 내보낼 수 없는 CryptoKey로 가져온다. 공유 코드를 만들기 위한 원래 32바이트 배열은 가져온 뒤 지운다. JavaScript 문자열·런타임 전체의 메모리 소거를 보장하는 규격은 아니다.

공유 코드는 키의 **padding 없는 Base64url 43문자**다. 앞뒤 공백은 입력 시 제거하지만 내부 공백이나 다른 알파벳은 거부한다. 디코딩 후 같은 표현으로 다시 인코딩되는 canonical 값만 허용한다. 짧은 PIN이나 사용자 비밀번호에서 키를 만들지 않는다.

파일의 권장 이름은 `envhandoff-<bundleId>.envhandoff`다. 프로젝트 표시명을 파일명에 넣지 않는다. 수신자가 파일명을 바꾸어도 열 수 있으며 파일명은 인증된 메타데이터가 아니다.

## 암호화된 내용

하나의 UTF-8 JSON 객체를 암호화한다. 송신 구현은 `JSON.stringify`를 사용하며, 수신 구현은 JSON 필드 순서에 의존하지 않는다.

```json
{
  "formatVersion": 1,
  "bundleId": "00000000-0000-4000-8000-000000000001",
  "projectLabel": "public-example",
  "environment": "development",
  "createdAt": "2026-09-11T00:00:00.000Z",
  "files": [
    { "path": "config/.env", "contentBase64": "REVNTz10ZXN0DQo=" }
  ]
}
```

- 위의 최상위 필드와 각 파일의 `path`, `contentBase64`만 허용한다. 누락·추가 필드·다른 자료형은 거부한다.
- `bundleId`는 UUID v4 문자열이다. `createdAt`은 실제로 존재하는 날짜의 `YYYY-MM-DDTHH:mm:ss.sssZ` UTC 문자열이다. 둘 다 발신자 인증이나 최신 상태의 증거가 아니다.
- `projectLabel`과 `environment`는 앞뒤 공백 제거 후 비어 있지 않아야 한다. 입력 기준 각각 최대 80·48 UTF-16 code unit이고 C0 제어문자와 DEL을 허용하지 않는다.
- `contentBase64`는 padding을 포함한 표준 Base64의 canonical 표현이다. 빈 파일은 빈 문자열로 표현한다.
- 줄바꿈·주석·BOM·인코딩·바이너리 값은 원본 바이트 그대로 보존한다. 설정값을 파싱하거나 실행하지 않는다.
- 프로젝트 표시명·환경·파일 경로·생성 시각은 암호화 영역에만 존재한다. 수신자는 전체 암호문 인증과 아래 유효성 검사가 끝나기 전에는 메타데이터·내용·다운로드를 제공하지 않는다.

## 크기와 공유 경로

파일 개수는 1~100개, 파일당 최대 1 MiB, 원본 합계 최대 10 MiB, 헤더·태그를 포함한 공유 파일은 최대 16 MiB다. 수신자는 공유 파일 길이를 먼저 확인하고, 인증 후 Base64 길이와 디코딩된 원본 크기·전체 합계를 다시 확인한다.

경로는 `/`로 구분한 상대 경로다. NFC로 정규화한 경로는 UTF-8 512바이트, 각 구성 요소는 255바이트까지 허용한다.

- 빈 경로 요소, `.`·`..`, 절대 경로, `\\`, `<>:"|?*`, C0/C1 제어문자, 지정된 방향 제어·제로폭 문자 범위를 거부한다. 정확한 문자 범위는 `validatePath`에 명시되어 있다.
- 경로 요소를 NFKC로 확인해 `.git`, 끝의 점·공백, Windows 예약 장치명 `CON`, `PRN`, `AUX`, `NUL`, `COM1`~`COM9`, `LPT1`~`LPT9`와 그 확장자를 거부한다. 정규화로 생기는 구분자나 예약 문자도 거부한다.
- 충돌 비교 키는 `NFKC → 대문자 → 소문자`다. 같은 키를 가진 경로와 한 파일이 다른 파일의 부모가 되는 경우(`a`, `a/b`)를 함께 거부한다. 웹에서 파일을 직접 배치하지 않더라도 생성·열기 양쪽에 같은 규칙을 적용한다.

다운로드 목록에는 전체 공유 경로를 표시하지만 브라우저에는 마지막 파일명으로 개별 다운로드를 요청한다. 폴더 생성·덮어쓰기·권한 설정은 이 웹 버전의 동작이 아니다. 후속 데스크톱은 이 규격 외에도 실제 OS와 파일 시스템 경로·링크·권한 검사를 수행해야 한다.

## 오류와 검증

형식 식별 실패, 미지원 버전, 크기·경로 오류, 입력 코드 형식 오류를 구분한다. 올바른 형식의 다른 키와 변조된 암호문은 같은 인증 실패로 처리한다. 인증에 실패한 데이터에서 파일 목록이나 부분 내용을 복구해 표시하지 않는다.

공개 벡터는 고정된 **테스트 전용 키·nonce**로 독립적인 Node `crypto` 구현에서 생성했다. 제품의 내보내기에서는 고정값을 사용하지 않는다. 자동 테스트는 해당 벡터 읽기, 새 키·nonce의 왕복, 잘못된 코드·변조·잘림, 인증된 잘못된 payload, 경로 충돌, 최대 100개·10 MiB 경계를 확인한다. 후속 Rust 코어도 같은 공개 벡터를 읽어야 한다.
