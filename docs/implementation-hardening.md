# 추가 점검 후 개선 설계

2026-10-08. 논리 오류·구조·성능 점검에서 확인한 여섯 항목을 개선한다. 운영 배포와 신규 전달 접수 재개는 별도다.

## 유지할 규칙

- Owner의 자동 파일 권한과 Member의 프로젝트 기본값·환경 예외를 유지한다.
- 네트워크 오류나 404만으로 업로드의 실패를 확정하지 않는다. 암호문·작업 ID·코드를 유지하며, 서버가 종료를 확정했을 때만 재시도 상태를 해제한다.
- 권한·기기 변경과 관련 전달 종료는 같은 DB 거래에서 수행한다. 종료된 전달은 권한 재부여로 살아나지 않는다.
- 삭제대장이 없거나 손상되면 접근을 차단한다. DB 복원으로 삭제 자료가 살아나면 다시 삭제한다.

## 변경 경계

| 항목 | 설계 | 검증 기준 |
| --- | --- | --- |
| 삭제대장 반복 처리 | 대장 전체 검증은 유지하고 DB의 적용 기록과 복원 흔적으로 재적용 여부 판단 | 반복 동기화 2 SELECT·0 쓰기, 롤백·이전/부분 복원 재삭제 |
| 업로드 취소 확정 | 사용자·조직·종류·예약 ID에 묶인 취소 기록을 DB에 저장; 늦은 예약을 차단 | 취소/생성 동시 요청, 업로드 중 취소, 완료 응답 유실, 영수증 정리 후 재시도 |
| 브라우저 자동 검사 | 기존 verify 함수 자동 탐색, 격리 Chrome과 localhost 모의 API로 실행 | 검증 실패·브라우저 오류·시간 초과 시 CI 실패, 저장소/프로세스 정리 |
| 웹 요청 중복 | pro-api에서 쿠키·CSRF·타임아웃·세션 만료·오류·업로드 종료 판정 공유 | 기존 오류 안내와 불확실한 결과의 작업 보존 |
| 순환 의존 | lifecycle 모듈로 요청·전달·공유 종료 규칙 이동 | 조직/사용자/요청/공유 범위 격리, 유지보수 전체 정리 |
| 카탈로그 N+1 | 조직 범위 일괄 조회 후 메모리에서 프로젝트·환경 조합 | 규모와 무관한 쿼리 수, Owner/Member 응답과 조직 경계 유지 |

삭제대장·조회, 업로드 복구, 브라우저 CI를 각각 병렬 담당하고 부모 작업에서 lifecycle·웹 요청 통합·문서·전체 검증을 맡는다.

## 취소 계약과 보존 기간

`POST /organizations/:orgId/shares/:id/cancel` 및 요청 아래 `/uploads/:id/cancel`은 `operationId`를 받는다. 아직 예약 행이 없으면 취소 기록을 남기고 `cancelled`를 반환한다. 진행 중 예약도 취소한다. 이미 완료된 전달은 `available`을 반환해 브라우저에 남은 코드와 링크를 복구한다. 완료 전달을 회수하는 `/revoke`는 별도 동작이다.

011 마이그레이션의 취소 기록은 30일 영수증 정리로 지우지 않는다. 사용자·조직 삭제에 연결되며 팀 업로드의 요청 기록이 영구 정리되면 함께 정리한다. 없는 예약에 대한 새 취소는 기존 생성 시도와 합산해 사용자별 10분 20회 한도를 적용한다. 자신의 기존 예약 취소는 이 한도로 막지 않는다.

## 확인 범위

성능 수치는 격리된 로컬 PostgreSQL의 동일 합성 데이터로 전후 비교한다. SQL 횟수는 회귀 검사로 고정하고 실행 시간은 참고값으로 기록한다. 삭제대장 파일 검증은 여전히 이력 수에 비례하며 전체 DB 거래 직렬화도 유지한다. 이번 변경으로 운영 부하 한계를 검증했다고 보지 않는다. 실제 결과는 [QA 기록](qa.md)에 남긴다.
