# EnvHandoff

[English](README.md) | **한국어**

**Git에 없는 개발 설정도, 동료에게 안전하게 건네기.**

EnvHandoff는 `.env`와 개발 설정 파일을 암호화해서 주고받는 도구다. 저장소를 clone한 뒤에도 따로 받아야 하는 설정을 파일 단위로 묶어 전달한다. 받는 사람은 별도 공유 코드로 묶음을 열고, 원본 파일을 꺼내 자기 프로젝트에서 사용한다.

웹에서 파일 전달과 다운로드를 먼저 제공하고, 이후 데스크톱 앱에서 프로젝트 폴더의 비교·적용·복구까지 이어간다. 현재 버전은 **0.0.1**이며, 일반 파일 공유와 실시간 전달을 로컬에서 실행할 수 있다.

## 이런 때 사용한다

- 새 팀원이 프로젝트를 시작할 때, Git에서 제외한 `.env`·`.env.local`과 필요한 설정 파일을 함께 건넨다.
- 개발 환경 설정이 바뀌었을 때, 전달할 파일만 골라 한 시점의 묶음으로 공유한다.
- 두 사람이 접속한 상태라면 실시간으로 전달하고, 접속 시간이 다르면 암호화한 공유 파일을 남긴다.

파일마다 상대 경로와 원본 바이트를 보존한다. 설정을 키별로 다시 입력하거나 특정 서비스 형식으로 변환할 필요가 없다. `.env` 외에도 사용자가 직접 고른 JSON 등의 개발 설정 파일을 같은 방식으로 다룬다.

## 두 가지 전달 방식

| | 공유 파일 | 실시간 전달 |
|---|---|---|
| 잘 맞는 상황 | 서로 접속 시간이 다를 때 | 두 사람이 동시에 접속해 있을 때 |
| 보내는 것 | 암호화한 `.envhandoff` 파일 | 일회성 연결 링크 |
| 전달 경로 | AirDrop·메신저·이메일 첨부 등 | 송신자 승인 후 relay가 암호문 중계 |
| 받는 사람 | 공유 파일과 별도 코드로 열기 | 링크 연결 후 별도 코드로 열기 |
| 완료 확인 | 앱은 상대의 수신 여부를 알 수 없음 | 받는 앱의 암호문 인증 응답으로 확인 |

두 방식 모두 **공유 코드는 파일·링크와 다른 대화 경로로 전달**한다. 계정 가입은 필요 없으며, 서로 아는 사람끼리 기존 개인 대화에서 상대를 확인하는 흐름이다.

## 웹과 데스크톱 앱

웹은 설치 없이 파일을 주고받는 입구다. 데스크톱 앱은 받은 설정을 로컬 프로젝트에 확인 후 적용하는 작업까지 맡을 예정이다.

| 기능 | 웹 0.0.1 — 현재 | 데스크톱 앱 — 계획 |
|---|---|---|
| 파일 선택 | 브라우저 파일 선택, 공유 경로 직접 확인·수정 | 프로젝트 폴더 선택, 설정 파일 후보와 Git 상태 확인 |
| 전달 | 암호화 파일 공유, 실시간 전달 | 같은 파일 규격과 relay로 웹과 주고받기 |
| 가져오기 | 인증 후 내용 확인·원본 다운로드 | 적용할 폴더를 골라 기존 파일과 비교 |
| 프로젝트 반영 | 사용자가 다운로드한 파일을 직접 배치 | 선택한 파일을 백업 후 추가·교체 |
| 되돌리기 | 프로젝트 파일을 직접 수정하지 않음 | 가져오기 전 상태로 복구 |
| 실행 환경 | 브라우저, 로컬 개발 실행 가능 | Tauri 2 기반 macOS·Windows 앱 예정 |

데스크톱 앱의 폴더 선택과 적용 흐름은 [데스크톱 설계](docs/app-design.md)에 정리했다.

파일의 지속적인 동기화와 팀 계정·권한·클라우드 보관은 현재 버전에 포함하지 않는다. 다음 단계는 웹의 실제 배포와 여러 기기·브라우저 검증이다. 데스크톱 앱과 팀 기능은 [제품 계획](docs/product-plan.md)을 따라 확장한다.

## 사용하기

**파일 보내기**

1. `파일 보내기`에서 필요한 파일을 고르고 공유 경로를 확인한다. 프로젝트 표시명과 환경 이름을 입력한다.
2. 공유 파일 또는 실시간 전달을 선택한다.
3. 공유 파일은 다운로드해서 상대에게 보내고, 공유 코드는 다른 대화 경로로 전달한다.
4. 실시간 전달은 연결 링크를 보낸 뒤 두 화면의 확인 숫자를 개인 대화로 비교하고 전송을 승인한다. 코드는 별도로 전달한다.

**파일 가져오기**

1. 홈의 `공유 파일 열기`에서 `.envhandoff`를 고르거나, 전달받은 연결 링크를 연다.
2. 공유 코드를 입력한다. 인증을 마치면 파일 목록과 공유 경로를 확인할 수 있다.
3. 필요한 원본 파일을 다운로드하고, 공유 경로를 참고해 자기 프로젝트에 직접 배치한다. 내용은 `내용 보기`를 누른 경우에만 표시한다.

실시간 전달의 100% 전송 뒤에는 수신 확인을 기다린다. 받는 앱이 암호문 인증을 마치고 응답해야 송신 화면이 완료된다. 연결이 끊기면 새 링크로 다시 연결하거나 같은 묶음을 공유 파일로 내려받는다. 다운로드와 수신 완료는 프로젝트에 적용했다는 뜻이 아니다.

파일은 최대 100개, 파일당 1 MiB, 원본 합계 10 MiB, 암호화 공유 파일 16 MiB까지 지원한다. 하위 폴더는 공유 경로에 `config/.env`처럼 입력한다. 같은 경로·대소문자 충돌·상위 폴더 이동·예약된 이름 등은 생성과 열기 모두에서 거부한다.

## 파일과 코드 처리

- Web Crypto의 AES-256-GCM을 사용한다. 새 묶음마다 독립적인 256비트 공유 코드와 96비트 nonce를 생성한다. 메타데이터와 원본 파일 바이트를 함께 암호화한다.
- 파일·공유 코드·열어본 내용·선택 상태는 현재 탭 메모리에만 둔다. 새로고침·탭 종료 후 복원하지 않는다. 분석 SDK, localStorage, IndexedDB, 서비스 워커를 사용하지 않는다.
- relay는 공유 코드를 받지 않는다. 연결 토큰은 파일 복호화 키와 별개다. 파일·암호문·키는 서버 저장소나 애플리케이션 로그에 기록하지 않는다. 요청 제한용 카운터만 Durable Object 저장소에 둔다.
- 다운로드한 파일과 클립보드에 복사한 코드는 사용자가 보관하는 사본이다. 앱은 저장 결과나 프로젝트 적용을 확인하지 않으며, 이미 전달한 사본을 회수하지 않는다.

파일 규격과 보안 경계는 [파일 형식 v1](docs/bundle-format-v1.md), 연결과 제한은 [relay 프로토콜](docs/relay-protocol.md)에 정리했다. 테스트 벡터와 소개 이미지에는 공개 가능한 예시만 사용한다. 실제 설정 파일·공유 코드·공유 파일은 저장소에 넣지 않는다. `.gitignore`는 `.env`·`.dev.vars` 계열과 공유 파일을 제외하며, 공개 예시 파일과 `fixtures/bundles/`의 테스트 벡터는 추적할 수 있게 둔다.

## 개발 시작

Node.js 24.21.0과 pnpm 12.3.4를 사용한다.

```sh
mise install
mise exec -- pnpm install --frozen-lockfile
mise exec -- pnpm dev
```

mise를 셸에 연동했다면 `pnpm dev`로 실행해도 된다. mise 없이도 위 버전의 Node.js와 pnpm을 설치하면 같은 pnpm 명령을 사용한다.

- 웹: <http://localhost:5173>
- 로컬 relay: <http://localhost:8787>
- 웹의 `/api` 요청과 WebSocket은 Vite가 로컬 relay로 연결한다. 두 앱을 함께 실행해야 실시간 전달을 사용할 수 있다.

로컬 개발에는 Cloudflare 로그인이나 배포가 필요 없다. 실제 기기에서 암호화하려면 HTTPS로 제공해야 한다. localhost는 브라우저의 보안 컨텍스트 예외로 사용할 수 있다.

## 명령과 구성

| 명령 | 동작 |
|---|---|
| `pnpm dev` | 웹과 로컬 relay 실행 |
| `pnpm build` | 웹 프로덕션 빌드와 Worker 배포용 번들 생성, 실제 배포 없음 |
| `pnpm lint` | Oxlint 검사 |
| `pnpm typecheck` | 전체 TypeScript 검사 |
| `pnpm test` | 암호화·파일 검증과 실제 로컬 workerd relay 통합 테스트 |
| `pnpm check` | lint·타입 검사·테스트·빌드 |
| `pnpm --filter @envhandoff/web preview` | 웹 빌드 미리보기; 실시간 전달 검증은 `pnpm dev` 사용 |

```text
apps/web/               React + TypeScript + Vite, 브라우저 파일 처리와 화면
apps/server/            Cloudflare Worker + Durable Objects relay
packages/protocol/      공통 연결 메시지·검증·제한
fixtures/bundles/       공개 파일 형식 테스트 벡터
docs/                   제품 계획·웹·데스크톱·파일 규격·relay 설계
  images/               README용 제품 스크린샷
```

Turborepo가 workspace 작업을 실행한다. 테스트와 개발 서버는 캐시하지 않는다. 결과물은 각 앱의 `dist/`에 생성하며 원격 캐시는 연결하지 않았다. `apps/desktop/`과 Rust 코어는 후속 작업이다. JS/TS 의존성은 루트 `pnpm-lock.yaml` 하나로 관리한다. 의존성 설치 스크립트는 필요한 esbuild·workerd만 `pnpm-workspace.yaml`에서 허용한다.

루트와 모든 workspace 패키지의 시작 버전은 `0.0.1`이다. 제품 계획의 기능 단계 v1.0·v2.0, 공유 파일의 형식 버전 1과는 구분한다.

## 검증과 배포 상태

웹 0.0.1은 소개 홈에서 실제 보내기·가져오기 화면으로 이어지며, 밝은 화면·어두운 화면과 모바일 너비를 지원한다. 데스크톱 앱은 후속 작업이다.

`pnpm check`로 암호 왕복, 공개 테스트 벡터, 잘못된 코드·변조·잘림·크기·경로 제한, relay 승인·역할 토큰·수신자 제한·ACK·중단·링크 재사용 방지를 검사한다. relay 테스트는 별도 포트와 임시 저장소에 실제 workerd를 띄우고 종료한다.

브라우저 검증은 Aside의 Chromium에서 공개 가짜 파일로 진행했다. 파일 선택 → 암호화 파일 다운로드 → 재열기 → 원본 다운로드와 두 탭의 실시간 전달에서 원본 바이트가 같음을 확인했다. 320·375·560·700·800·1024px iframe과 데스크톱 화면에서 반응형 배치를 확인했다. 긴 경로와 미리보기를 포함해 가로 넘침이 없고 밝은 화면·어두운 화면에서 동작했다.

Cloudflare에는 아직 배포하지 않았다. 배포할 때는 정적 웹과 relay를 같은 origin의 `/api/*` 아래 연결하고, `apps/server/wrangler.jsonc`의 `WEB_ORIGINS`를 실제 HTTPS 웹 origin으로 설정해야 한다. 웹과 Worker는 별도 빌드·배포 대상으로 유지한다. 무료 플랜과 SQLite Durable Objects를 사용하며 유료 사용량을 자동으로 활성화하지 않는다. 실제 Cloudflare 한도·장애, 서로 다른 두 기기, Safari·Firefox와 모바일 기기 검증은 배포 전 작업으로 남아 있다.

제품의 후속 범위는 [웹 설계](docs/web-design.md), [제품 계획](docs/product-plan.md), [데스크톱 설계](docs/app-design.md), [공통 용어](CONTEXT.md)를 따른다.
