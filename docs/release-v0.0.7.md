# v0.0.7 배포 절차

현재 정상 운영 버전은 v0.0.6, SHA는 `c4cbc4d6c9a15f246f515ac6d14ac32049a2eb6c`다. v0.0.7은 Owner 자동 권한·Member 프로젝트 기본값/환경 예외, 업로드 취소 확정, 조회 성능과 브라우저 CI를 포함한다.

## 검토한 DB 변경

- 010: `project_permissions` 추가, 모든 기존 환경에서 공통인 권한만 기본값으로 복사, 동일한 환경 행은 상속으로 전환. 기존 Member의 실효 권한을 유지하고 Owner에게 자동 권한을 제공한다.
- 011: `upload_cancellations`와 인덱스 추가, 새 취소 기록을 생성 한도에 합산한다.
- API 시작 시 두 파일은 기존 마이그레이션의 한 거래·자문 잠금 아래 적용된다. Compose·볼륨·접수 설정·인증 비밀값은 바꾸지 않는다.

## 적용 순서

1. PR와 정확한 main SHA의 전체 CI를 확인하고 `release/v0.0.7`을 생성한다. 이전 정상 API 이미지·배포 ID, Worker 버전, PostgreSQL 컨테이너·볼륨을 비공개 작업 기록에 보존한다.
2. 운영자 SSH로 **이 API 도메인만** 외부 변경·전달 요청을 점검 상태로 전환한다. 무쿠키 GET `/auth/session`의 상태 검사와 컨테이너 내부 health는 유지한다. 무료 웹·relay 및 다른 서비스는 중지하지 않는다. 기존 API 프로세스를 정상 종료하고 종료를 확인한다.
3. 기존 권한 메타데이터와 스키마를 암호화해 비공개로 백업한다. 이번 변경의 복구에 필요한 조직·소속·팀·프로젝트·환경·권한 자료만 대상으로 삼고, 공유 토큰·세션·도전·재시도 자료와 암호문 객체는 백업하지 않는다. Member 실효 권한은 `(조직, 환경, 사용자, receive, send, external_share)`로 정규화해 전후 비교 자료를 보관한다. 없는 행은 0과 같게 비교한다. 백업 보존은 최대 7일이다. 독립 삭제대장은 그대로 둔다.
4. `Deploy production`을 해당 버전 브랜치에서 실행한다. `migration_preflight_sha`에는 위 준비를 실제 완료한 정확한 배포 SHA만 입력한다. `Verify release` 통과 후 기존 `production` 환경에서 같은 SHA를 승인한다. 이 입력은 환경 승인을 대체하지 않는다.
5. `.github/scripts/migration-gate.mjs`는 정확한 이전 SHA·버전·ref, 추가된 010/011의 고정 해시, 변경 없는 Compose, 정확한 사전 준비 SHA를 모두 검사한다. 그 외 DB/Compose 변경은 계속 거절한다. CI의 SSH 권한은 기존 관리 API 터널 범위에서 넓히지 않는다.
6. 기존 승인형 작업이 API 서비스만 배포한다. 시작 마이그레이션 완료, 버전 11, 기존 PostgreSQL 컨테이너·볼륨, 삭제대장·API health, Member 권한의 각 비트 보존과 Owner 자동 권한을 확인한다. 기존 API를 다시 시작하지 않는다.
7. 같은 SHA의 웹·relay 배포와 공개 assets·health를 확인한다. 점검 상태를 유지한 채 기존 웹 세션과 OAuth 흐름을 만료시켜 구형 화면의 권한 변경을 차단한다. 기기 키·신뢰·팀 소속은 초기화하지 않는다. 사용자는 새 화면에서 다시 로그인한다.
8. 모든 확인 후 해당 API의 점검 설정만 복구한다. 무쿠키 세션 401, 웹 버전·assets, relay health, 실제 API/Worker SHA를 재확인한다. 백업의 삭제 기한을 설정하고 성공한 SHA에 서명 태그를 만든다.

## 실패 처리

API 배포·권한 비교·웹 확인이 실패하면 외부 요청 차단을 유지한다. SQL 거래 자체의 실패는 롤백되지만, **010/011 적용 후 구형 API로 자동 복구하지 않는다.** 구형 API는 프로젝트 권한의 멤버 정리와 취소 기록을 모르므로 안전한 호환 버전이 아니다. 수정 배포를 우선하며 메타데이터 복원이 필요하면 [복원 절차](operations.md#과거-백업에서-복원할-때)에 따라 기존 전달을 닫고 현재 권한을 다시 검토한다. 삭제대장·DB·객체 볼륨을 초기화하지 않는다.

구형 웹도 환경 예외만 권한으로 표시할 수 있으므로 세션 만료와 새 화면 로드를 배포 절차에 포함한다. `PRO_ACCEPT_NEW_TRANSFERS`의 변경은 이 릴리스에 포함하지 않는다.
