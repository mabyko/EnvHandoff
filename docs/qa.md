## 완료 근거

- 제품 화면 분리 당시 `pnpm check`: API 73개·웹 24개·relay 9개, 총 **106개 PASS**. 전체 타입 검사·lint·빌드 PASS(12/12 작업, 변경 없는 일부 작업은 캐시 재사용). 후속 병렬 구현 결과는 아래에 별도 기록한다.
- 자동 검사: [전달](../apps/api/tests/transfers.test.ts), [요청](../apps/api/tests/requests.test.ts), [팀 외피](../apps/web/tests/team-crypto.test.ts), [조직·권한](../apps/api/tests/organizations.test.ts), [기기](../apps/api/tests/devices.test.ts), [재인증](../apps/api/tests/security.test.ts).
- 이번 Chrome 검사: 서로 격리된 송신/수신 컨텍스트, 실제 React 컴포넌트·AuthApi와 전용 PostgreSQL 테스트 스키마, 가짜 계정·파일을 사용했다. 전체 OAuth 로그인이나 운영 HTTP 서버 설정의 검증을 대신하지 않는다.
- 화면에서 기기 등록 → 요청 → 승인 → 잘못된 지문 거부 → 정상 지문 고정 → 암호화 업로드 → 송신자 로그아웃 → 수신 → ACK → 재다운로드 → 회수를 확인했다. 회수 후 다운로드 도전 410, 다운로드 버튼 제거, 과거 ACK 유지.
- 다운로드 Blob 34바이트의 BOM·CRLF와 `services/api/.env` 배치 경로 보존. 송신 화면의 viewport와 scrollWidth 모두 390px. 파일이 남아 있을 때 beforeunload 경고와 이동 취소를 확인했다.
- 파일 선택은 도구의 파일 경로 접근 제한으로 브라우저 내 합성 File과 change 이벤트를 사용했다. 실제 OS 파일 선택 창·디스크 저장 완료·두 물리 기기의 검증과 구분한다.
- 이번 브라우저 검사의 로컬 기기 키·지문·탭과 테스트 서버·해당 스키마·객체를 정리했다. 정리 후 테스트 DB에 별도 스키마 1개가 남아 있어 전체 DB가 비었다고 표시하지 않으며, 이번 검사 소유가 아닌 데이터는 삭제하지 않았다.
- 이전 세션의 인증 앱 등록·재인증, 기기 회수, 요청 승인·거절·Owner 취소·멤버 목록 격리·키보드 검사 근거는 [진행 기록](pro-v3-spec.md)에 있다. 이번 세션에서 재실행한 것으로 표시하지 않는다.

- 외부 공유 Chrome 검사: 외부 공유 권한만 있는 미등록 기기의 생성 → 비회원 미리보기 → 잘못된 코드 거부(ACK 없음) → 정상 복호화·ACK → 링크 재발급 → 기존 링크 404 → 같은 코드 재사용 → Owner 회수 후 404·과거 ACK 유지. 미리보기에는 다운로드·ACK가 없었고 fragment가 제거됐다. 새로고침 시 토큰 없음 안내, 코드 복구 불가 안내를 확인했다.
- 외부 공유 다운로드 Blob의 35바이트 BOM·CRLF와 `services/web/.env` 경로를 확인했다. 수신 화면 390px에서 가로 넘침 없음. 공유 상세 링크의 해당 항목 포커스·잘못된 조직 접근 차단, 같은 세션 새 탭·포커스 시 링크 유지, 다른 탭 로그아웃 시 계정·링크 즉시 제거를 확인했다. 실제 OAuth 왕복은 포함하지 않는다.
- 장애 검사는 [전달](../apps/api/tests/transfers.test.ts)·[객체 스트림](../apps/api/tests/objects.test.ts)·[외부 공유](../apps/api/tests/shares.test.ts)·[복원 차단](../apps/api/tests/restore-safe.test.ts)에 남겼다. 실제 프로세스 SIGKILL, 삭제 실패, 응답 유실, 일부 다운로드 중단과 공유 합산 한도를 주입한다. 운영 절차는 [운영과 복원](operations.md)을 따른다.


## Pro 제품 화면 후속 검사

- 시작·초대, 요청/공유 목록·상세·생성, 프로젝트 목록·환경 상세, 팀 관리, 내 설정을 분리했다. 프로젝트 환경에서 공유 만들기로 이동해 선택 유지·실제 암호화 업로드·상세 코드 표시를 확인했다. 요청 목록에서 상세를 열고 가짜 sender의 승인 상태 갱신을 확인했다.
- [페이지 회귀 검사](../apps/web/tests/pro-pages.browser.ts)의 `verifyProPages()`를 격리 Chrome에서 실행해 5묶음 PASS: 요청 목록/상세/생성, 환경 선택, 공유 목록/상세/생성, 생성·화면 왕복 후 코드 유지, 접근 불가 상세에 다른 항목 비노출. 모의 HTTP 검사이며 실제 API 검사를 대신하지 않는다.
- 실제 React·PostgreSQL 전용 fixture에서는 Owner의 역할 승격 저장, Member의 초대·역할·삭제 관리 컨트롤 비노출, 기본팀 선택 숨김, 상세 포커스와 조직 없는 주소 정규화를 확인했다. 테스트 조직의 삭제 확인→시작 화면·소속 없음으로 복귀하고 계정 세션은 유지됨을 확인했다. 실제 계정이나 운영 조직은 수정하지 않았다.
- 브라우저 뒤로/앞으로 이동 후 공유 코드 유지, 메뉴 이동 경고 취소 후 주소·코드 유지 PASS. `history.go` 취소 복원은 확인 응답을 false로 주입해 주소·history index·링크 보존을 검증했다. 이 history 검사에서 네이티브 대화상자의 도구 제어 결과는 일관되지 않아 실제 사용자 클릭 검증으로 표시하지 않는다.
- 세션 조회에 503을 주입해 공유 코드 유지·서버 작업 잠금과 연결 복구 후 코드 유지 PASS. 실제 401/만료/로그아웃과 일시적 서버 오류를 구분했다.
- 375px 세로와 812px 가로 viewport에서 가로 넘침 없음. 밝은·어두운 팀 관리 화면을 캡처해 확인했고, 검사한 최종 화면 콘솔 경고·오류 없음. 실제 모바일 기기·Safari·Firefox 검사와 구분한다.
- [조직 수명 검사](../apps/api/tests/organizations-lifecycle.test.ts)는 재인증·마지막 활성 Owner·동시 강등·이전·초대 폐기·조직 삭제 후 요청/공유 종료·다른 조직과 기기 보존을 확인한다.

### 패스키 삭제 안내 후속 수정

- 사용자 실제 패스키 등록 후 삭제 버튼에서 `reauthentication_required` 안내가 발생했다. 등록 자체는 재인증이 아니며, 하나뿐인 인증 수단은 재인증 후에도 삭제할 수 없다. 화면이 이 조건을 클릭 전에 설명하지 않았던 문제다.
- `3a61fe2`에서 패스키·TOTP 삭제에 같은 사전 안내와 비활성화 조건을 적용했다. 서버의 본인 확인·마지막 수단 보호는 변경하지 않았다. [실제 컴포넌트 회귀](../apps/web/tests/pro-security.browser.ts)는 수정 전 실패, 수정 후 마지막 패스키·마지막 TOTP·미인증·삭제 성공·인증 만료의 5묶음 PASS. 기존 API 보안 5개·웹 27개, 웹 lint·타입·운영 빌드 PASS.
- 운영 Worker 버전 `d0e2e17a-5e24-49cc-9991-4ae31cb3a83c`로 웹을 재배포했다. Aside에서 로그인 유지, 실제 패스키 본인 확인 완료, 마지막 수단 안내와 삭제 버튼 비활성화를 확인했다. 사용자의 인증 수단을 검사 목적으로 삭제하지 않았다. API 코드는 그대로 `8b5fe2d`다.
- 실제 패스키 등록·본인 확인은 확인 범위에 추가했다. 실제 TOTP·패스키 취소·추가 장치와 위의 나머지 출시 검사는 여전히 남아 있다.

### API 공개 접속 보완

- 최종 API 코드 `4faba82`, Openship 배포 `dep_Hq3-m65axlBi1FGU`는 `ready`. API·PostgreSQL 모두 `healthy`, 재시작 횟수 0. API는 `127.0.0.1:20000`으로만 연결하고 DB 공개 포트는 없다. 신규 전달과 Auto Deploy는 계속 꺼뒀다.
- API DNS를 Cloudflare 프록시로 전환했다. 기존 `*.envhandoff.mabyko.com` edge 인증서를 확인해 API 주소와 OAuth callback을 유지했다. API 호스트에만 원본 TLS `Full (strict)`, HTTPS 요청 비밀 헤더, 자동 탐색 경로 차단, IP당 120건/10초의 순간 요청 제한을 적용했다. 비밀값은 API 런타임과 Cloudflare 규칙에만 설정하고 저장소·웹에는 넣지 않았다.
- 인증서 검증을 생략하지 않은 공개 경로의 무쿠키 `/auth/session`, `/organizations`, `/security`는 401, 웹 CORS preflight는 204, 외부 Origin은 403. 원본 IP에 정확한 Host/SNI로 접속하면 403이며, 가짜 Cloudflare·forwarded·비밀 헤더를 넣어도 403이다. 공개 경로의 가짜 비밀 헤더는 Cloudflare가 덮어써 정상 401을 반환한다. `/.env`, `/.git/config` 탐색은 edge에서 403이다.
- 실제 Aside 로그인 세션으로 새로고침 후 `mabyko` Owner와 워크스페이스 화면을 확인했다. 도메인·쿠키·등록한 패스키는 바꾸지 않았다.
- 클라이언트 IP/HTTP 경계 테스트 2개, 인증·보안·조직 회귀 21개, API typecheck·lint PASS. 서로 다른 사용자 IP, IPv6 정규화, 잘못된/중복 비밀 헤더, 직접 접속, 로컬 healthcheck 예외를 검사했다. 운영 서비스에 임계치를 넘기는 부하 시험은 하지 않았다.
- 중간 IP 대역 방식은 Openship의 전역 real-IP 변환으로 정상 요청도 403이 되어 설정을 비활성화하고 복구했다. 최종 구현은 zone 비밀 헤더를 검증한다. 별도 배포 한 건은 이미지 생성 후 진행이 멈춰 취소했고, 재배포 성공 후 위 결과를 확인했다.
